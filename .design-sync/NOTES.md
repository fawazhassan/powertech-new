# design-sync notes — powertech-digital

Repo is a **Next.js 15 app, not a packaged design system**: no dist/, no Storybook, no
library build. The sync runs the package shape in explicit-entry mode.

- **Entry**: `.design-sync/entry.ts` is a hand-written barrel re-exporting the site's real
  components (`components/ui/button.tsx`, `components/ui/card.tsx`, `components/header.tsx`,
  `components/footer.tsx`). New components must be added to BOTH the barrel and
  `componentSrcMap` in config.json.
- **Next shims**: `next/link` and `next/image` are aliased to `.design-sync/shims/*.tsx` via
  `compilerOptions.paths` in `.design-sync/tsconfig.sync.json` (the converter's
  tsconfig-paths plugin resolves bare specifiers too). Link renders `<a>`; Image renders
  `<img>` with an `onError` hide (see logo note). The paths block also carries `@/*` — the
  plugin does NOT follow `extends`, so paths must stay inline in that file.
- **Header logo**: `/assets/images/logo.png` (public/) doesn't exist outside the site, so the
  image shim hides the broken img on error; the "PowerTech Digital" brand text carries the
  identity in cards and designs. If the user ever wants the real mark, inline it as a data
  URI in `components/header.tsx` itself.
- **Tailwind CSS is generated, not shipped by the repo**: `cfg.buildCmd` compiles
  `.design-sync/generated/theme.css` from `app/globals.css` via
  `.design-sync/tailwind.sync.config.ts` (extends the site config; content globs =
  `components/**`, `app/**`, `.design-sync/previews/**`; safelist covers the brand utility
  families named in conventions.md). **Run buildCmd before package-build whenever previews
  or site pages change class vocabulary** — a class used only in a preview won't exist until
  theme.css is recompiled.
- **Fonts**: Inter via a Google Fonts `@import` in `.design-sync/tailwind.input.css`
  (`[FONT_REMOTE]`, expected). The site loads Inter via next/font; the input CSS mirrors it
  with a static body font-family rule.
- **Lumina Refined (2026-07-08)**: the site's style comes from
  `templates/lumina-refined/LuminaRefined.dc.html` in the Claude Design project — deep
  emerald #047857, indigo #4F46E5, canvas #F7FAF9, Instrument Serif italic accents,
  IBM Plex Mono micro-labels, gradient hairlines, dot grids, offset-shadow buttons.
  `bg-secondary` is now WHITE with ink foreground (the white ink-border button look) —
  it is no longer an emerald twin of primary.
- **Signature utilities** (`mono-label`, `serif-accent`, `text-gradient-brand`,
  `hairline-gradient(-center)`, `dot-grid(-dark)`) live in `app/globals.css`
  `@layer components` — they tree-shake like utilities, so the sync tailwind config
  SAFELISTS them; keep that list in step with globals.css.
- **Font vars**: `--font-serif-accent`/`--font-mono-label` come from next/font on the
  site; `.design-sync/tailwind.input.css` defines them at `:root` (plus the 3-family
  Google Fonts import) so the DS bundle is self-sufficient outside Next.
- **Card viewports**: Header/Footer use `cardMode: column` with `viewport: 1280x…` — below
  1024px (Tailwind `lg`) Header renders its mobile hamburger state and the desktop nav
  disappears from the card.
- Playwright: chromium build 1228 was already cached (`~/Library/Caches/ms-playwright`);
  latest `playwright` npm release pinned the same build. Installed in `.ds-sync/`.

## Re-sync risks

- `theme.css` is regenerated by buildCmd; if `tailwind.config.ts` or `app/globals.css`
  change, conventions.md's class/color claims may drift — re-validate them against the
  fresh `_ds_bundle.css` (the conventions step does this on every re-sync).
- Preview class vocabulary must stay inside the tailwind content globs/safelist; a new
  class in a preview only works after re-running buildCmd.
- The next/link & next/image shims track Next's public prop surface — a Next major bump
  could add props the shims drop silently; eyeball Header/Footer cards after upgrades.
- `.design-sync/entry.ts` + `componentSrcMap` are a manually maintained pair — a component
  added to the site but not both of these silently stays out of the sync.
- Mobile/interactive states (Header hamburger menu open) are not statically renderable —
  skipped by design.
